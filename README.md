# PaymentGuard API

**A local, educational C# / ASP.NET Core 10 REST API for simulated transaction review.**

PaymentGuard is a portfolio exercise demonstrating .NET API development, validation, layered code organisation, SQLite persistence through Entity Framework Core, automated testing and CI. It does **not** process payments, perform fraud detection, make real credit decisions or contact banks. All examples use invented merchant references and synthetic amounts.

## Demonstration

| Example | Rule result | Reason |
| --- | --- | --- |
| EUR 49.95 | `APPROVED` | `BELOW_REVIEW_THRESHOLD` |
| EUR 1,450.00 | `REVIEW` | `HIGH_AMOUNT` |

The simple rule marks EUR amounts **at or above €1,000** for manual review. This is not a real risk model; `APPROVED` means only that the demonstration threshold was not met.

## Stack

- **C# / .NET 10** with ASP.NET Core Minimal APIs
- **Entity Framework Core + SQLite** for file-backed persistence
- **xUnit v3** for automated tests, plus 12 dependency-free behaviour checks
- **GitHub Actions** for build and test on pushes and pull requests

## Getting started

Requirements: .NET 10 SDK, internet access to restore NuGet packages, PowerShell (commands below) or equivalent shell.

```powershell
dotnet --version
dotnet restore .\PaymentGuard.Api\PaymentGuard.Api.csproj
dotnet restore .\PaymentGuard.Tests\PaymentGuard.Tests.csproj
dotnet build .\PaymentGuard.Api\PaymentGuard.Api.csproj --no-restore
dotnet run --project .\PaymentGuard.Checks\PaymentGuard.Checks.csproj
dotnet test .\PaymentGuard.Tests\PaymentGuard.Tests.csproj --no-restore
```

Start the local API:

```powershell
dotnet run --project .\PaymentGuard.Api\PaymentGuard.Api.csproj --urls http://127.0.0.1:5080
```

Keep that terminal open. In a separate PowerShell window:

```powershell
Invoke-RestMethod 'http://127.0.0.1:5080/health'
$body = @{ amount = 250.00; currency = 'EUR'; merchantReference = 'DEMO-LOCAL-001' } | ConvertTo-Json
$tx = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:5080/api/transactions' -ContentType 'application/json' -Body $body
$tx
Invoke-RestMethod "http://127.0.0.1:5080/api/transactions/$($tx.id)"
```

Expected result: HTTP 201 when creating a valid synthetic transaction, an ID generated by the API, and a subsequent HTTP 200 when retrieving that ID.

### Verify persistence across a clean restart

1. Stop the API in its own terminal using **Ctrl+C**. Ensure no other server is listening on port 5080.
2. Start it again using the command above from the *same project directory*.
3. Retrieve the transaction using its original ID. The same data after restart verifies file persistence.

On Windows, inspect port ownership with `Get-NetTCPConnection -LocalPort 5080 -State Listen -ErrorAction SilentlyContinue | Select-Object LocalAddress,LocalPort,OwningProcess` before attempting to restart. Do not kill arbitrary processes.

SQLite creates `PaymentGuard.Api/App_Data/paymentguard.db` when the API first starts; the database and associated journal files are ignored by Git.

## API contract

| Method | Path | Behaviour |
| --- | --- | --- |
| GET | `/health` | Basic health response |
| GET | `/` | Demo metadata and disclaimer |
| POST | `/api/transactions` | Validate, assess threshold and store synthetic record; 201/400 |
| GET | `/api/transactions` | List stored demo transactions |
| GET | `/api/transactions/{guid}` | Retrieve one record; 200/404 |

Example request:

```json
{
  "amount": 1450.00,
  "currency": "EUR",
  "merchantReference": "DEMO-ORDER-002"
}
```

Example fields in the response: `id`, `amount`, `currency`, `merchantReference`, `decision`, `reasonCode`, `createdAtUtc`.

Validation restricts transactions to EUR, positive amounts no greater than 100,000, at most two decimal places and an alphanumeric synthetic reference with a limited character set. The API generates the ID, decision and timestamp on the server.

## Design decisions and limitations

See [architecture](docs/ARCHITECTURE.md), [engineering decisions](docs/PHASE2_DECISIONS.md) and [interview notes](docs/INTERVIEW_NOTES.md).

Important boundaries:
- Localhost use only; **no public deployment**, authentication, authorisation or rate limiting.
- No idempotency keys or transactional banking guarantees; duplicate requests may create duplicate records.
- `EnsureCreated` is suitable for a disposable demo, not a schema migration strategy.
- The threshold is illustrative, not fraud detection, and `REVIEW` is not an accusation or customer decision.
- Do not use real customer details, payment card information, bank accounts or production secrets.
